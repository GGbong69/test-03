# 적응형 BGM

`docs/adaptive_bgm/godot_adaptive_bgm_spec.md` 의 구현이다.

네 편곡을 **한 타임라인에 묶어 계속 틀어 놓고 게인만 민다.** 그래서 상점에
들어가도 음악이 처음으로 안 돌아간다 — 마디 열둘에 있었으면 상점 편곡의
마디 열둘로 이어진다. 발라트로가 그렇게 들리는 이유가 이것이고, 곡을 갈아
끼우는 방식으로는 흉내가 안 난다.

- 고닷 **4.6.3-stable (official)** 에서 만들고 돌렸다. `AudioStreamSynchronized`
  는 4.3 부터라 그대로 쓴다 — 명세의 4.0~4.2 대안은 안 썼다.
- 플랫폼 Windows. 헤드리스 검사에서 오디오 드라이버는 `Dummy` 다.

## 지금 상태 — 켜져 있지 않다

`scripts/game.gd` 의 `MUS_ADAPTIVE` 가 **false** 다. 게임 음악은 아직
`game.gd` 쪽이 쥐고 있다 — 곡을 **나갔다 들어오는** 방식(0.55초 나감 ·
0.10초 숨 · 0.75초 들어옴)이고, 한 번에 한 곡만 울린다.

여기 적힌 어긋남이 바로 그 방식을 고른 이유이기도 하다. 겹쳐 넘기려면
두 곡이 겹치는 동안 박자가 맞아야 하는데 이 넷은 안 맞는다.

이유는 코드가 아니라 **에셋**이다. 이 방식은 네 파일이 *같은 곡의 편곡*
이어야 성립하는데, `assets/music` 의 넷은 그게 아니다. 재본 값:

| | lobby | select | game | boss | 명세 요구 |
|---|---|---|---|---|---|
| 템포 | 85.66 | 85.26 | 85.35 | 85.68 BPM | 동일 |
| 길이 | 61.894 | 61.854 | 61.973 | 61.574초 | ±0.001초 |
| 마디(4/4) | 21.97 | 21.96 | 22.00 | 21.86 | 동일 정수 |
| 앞 무음 | 173 | 200 | 209 | 45ms | 동일 시작점 |
| 끝 1초(가운데 대비) | −39.7 | −18.7 | −66.7 | −6.4dB | 루프 연결 |
| lobby 와의 상호상관 | — | 0.05 | 0.06 | 0.10 | 같은 곡 |

템포가 0.42 BPM 어긋나 있어서 62초를 한 바퀴 돌면 **반 박이 밀린다.** 셋은
끝에서 페이드아웃하므로 같은 순간에 음악이 통째로 사라진다. 지금 켜면
예전 방식보다 나빠지고, 잘라 붙여서 고칠 수 있는 종류의 어긋남도 아니다 —
서로 다른 곡이다.

그래서 명세의 `missing_assets` 조항을 따랐다: **직접 만든 동일 길이 시험
신호**를 `tracks/` 에 넣었다.

## 켜는 법

1. `tracks/` 의 넷을 실제 편곡으로 갈아 끼운다(아래 계약을 지킬 것).
2. 넷의 `.import` 에서 `edit/loop_mode` 를 Forward(값 2)로 둔다.
   WAV 면 `compress/mode=0`(PCM)을 권한다.
3. `music_config.json` 의 경로와 `music_meta` 를 실제 값으로 고친다.
4. 계약을 맞췄는지 먼저 잰다. 여기서 걸리면 게임에서도 걸린다:

   ```bash
   godot --headless --script scripts/tools/probe_music_assets.gd
   ```

5. `scripts/game.gd` 의 `const MUS_ADAPTIVE` 를 `true` 로 바꾼다.

`MUS_ADAPTIVE` 를 켜면 `game.gd` 의 `mus_*`(플레이어 둘·크로스페이드·보스
속도)는 통째로 쉰다. 둘이 같이 울리면 안 되기 때문이다. **보스 판에서
음악이 빨라지는 것(`MUS_RUSH_*`)도 같이 쉰다** — 적응형 쪽은 편곡을 바꾸는
방식이라 속도를 미는 자리가 없고, 명세도 "게임 속도에 따른 음악 피치 변경"
을 범위 밖으로 뒀다.

버스는 **설정 화면이 계속 쥔다.** `music_config.json` 의 `owns_bus` 는
false 로 둔다 — 명세가 버스를 한 곳만 만지라고 했고, 이 게임에서 그 한 곳은
`game.gd` 의 `_apply_vol` 이다. 관리자는 값을 받아 두기만 한다.

## 에셋 계약

| 상태 | 경로 | 언제 |
|---|---|---|
| Main | `tracks/main.wav` | 로비·판 선택·보통 판 위 |
| Shop | `tracks/shop.wav` | 상점 |
| Aim | `tracks/aim.wav` | 보통 판에서 조준 중 |
| Final | `tracks/final.wav` | **보스 판**(조준보다 세다) |

우선순위는 `Shop > Final > Aim > Main` 이고 `music_state_adapter.gd` 한
곳에서만 읽는다. 명세의 "마지막 라운드"를 이 게임에서는 **보스 판**으로
옮겨 읽었다 — 마지막 라운드의 보스만 Final 로 잡으면 여덟 보스 중 일곱이
평범한 판과 같은 소리가 되기 때문이다.

넷이 지켜야 하는 것:

- 같은 BPM·박자표·마디 수, 같은 화음 진행 타이밍
- 같은 샘플레이트·채널 수·**디코딩 후 프레임 수**
- 같은 시작점(공통 첫 박이 같은 프레임에)
- 같은 전체 길이와 루프 시작·끝
- 편곡별로 앞 무음을 다르게 자르지 말 것
- 크로스페이드 중 음량이 튀지 않게 맞출 것

관리자는 길이 차가 **0.001초**를 넘으면 시작을 통째로 거절한다. 셋만
준비된 채로 울리면 빠진 편곡이 "조용한 자리"로만 나타나서 원인을 못 찾는다.

## 지금 들어 있는 시험 신호

`scripts/tools/make_music_test.py` 가 만든다. 다시 만들려면:

```bash
python scripts/tools/make_music_test.py
```

84.0 BPM · 4/4 · 8마디 · **1,008,000 프레임(22.857143초)** · 44.1kHz 모노
16비트 PCM. 넷이 프레임까지 같다. BPM 을 84 로 고른 것은 44100 을
`84/60` 으로 나눈 값이 31500 프레임으로 딱 떨어지기 때문이다 — 소수점이
남는 템포는 마지막 마디에서 어긋나고, 그 어긋남이 명세가 막으려는
드리프트다.

넷은 **같은 화음 진행(Am–F–C–G)에 층만 다르게** 얹었다. 그래야
크로스페이드가 음악으로 들린다.

| | 층 |
|---|---|
| Main | 패드 + 베이스 + 하이햇 |
| Shop | 패드 + 아르페지오 (드럼 없음) |
| Aim | 패드 + 베이스 + 뒷박 펄스 + 하이햇 |
| Final | 패드 + 베이스 + 킥·스네어 + 선율 |

패드가 넷 다에 있다. 명세가 선형 진폭 보간을 고른 전제(공통 악기가 겹친다)
가 그것이고, 그래서 이 넷에서는 그 곡선이 맞다.

루프 이음매는 **겹쳐 접어서** 없앴다 — 8마디보다 길게 그린 뒤 넘친 꼬리를
맨 앞에 더한다. 잔향이 루프를 넘어 이어진다.

형식이 WAV 인 것은 명세가 선호하는 OGG 를 못 썼기 때문이다. 이 환경의
`soundfile`(libsndfile) vorbis 인코더가 헤더 4333바이트만 쓰고 프로세스를
죽인다(exit 127, 프레임 수 0). 명세가 대체로 허용한 PCM WAV 로 갔고,
44.1kHz 모노는 프로젝트 믹스레이트와 같고 내용이 어차피 모노라 크기만
절반이 된다. 넷 합쳐 8.1MB, 메모리도 같다.

## 돌리는 법

**자동 검사** — T01~T11 과 줄인 T14:

```bash
godot --headless --script scripts/tools/probe_bgm.gd
```

**긴 검사** — 명세의 30분:

```bash
BGM_SOAK_SECONDS=1800 godot --headless --script scripts/tools/probe_bgm.gd
```

**손으로 듣기** — 네 상태 단추와 진단이 붙은 창:

```bash
godot --path . tests/audio/music_test.tscn
```

**게임 쪽 연결** — 화면별 상태와 우선순위:

```bash
godot --headless --script scripts/tools/probe_music.gd
```

T14(30분·10회 루프 이상, 0.1~0.3초 간격 무작위 전환)는 `BGM_SOAK_SECONDS=1800`
으로 따로 돌렸다. **날것 그대로의 출력이 `outputs/bgm_soak_30min.txt` 에 있다**
— 엔진이 종료할 때 내는 잡음까지 안 지우고 두었다. 캡처를 다듬으면 캡처가
아니게 된다.

30분과 10회 루프를 **둘 다 채웠을 때만** pass 로 적히고, 못 채우면 얼마나
돌았는지와 함께 not_run 으로 남는다 — 줄여 돌린 것을 통과라고 쓰면 검사가
아니다. 이 자리는 한때 조건과 상관없이 "줄여 돌렸다"를 찍고 있었고, 30분을
채운 날에도 같은 말을 해서 결과가 사실과 달랐다. 지금은 실제 값으로 갈린다.

`underrun` 은 **어느 경우에도 못 쟀다.** 헤드리스의 드라이버가 `Dummy` 라
버퍼가 빌 일 자체가 없다. 정적 메모리는 30분에 +277KB 로, 새는 것으로 볼
크기가 아니다(검사는 4MB 를 넘으면 fail 로 잡는다).

**믿으면 안 되는 것:** 위 검사는 전부 `Dummy` 오디오 드라이버에서 돌았다.
게인 계산·상태 기계·신호는 이걸로 증명되지만, **실제로 어떻게 들리는지는
아무것도 증명하지 않는다.** 하위 스트림이 정말 샘플 단위로 붙어 있는지도
마찬가지다 — `get_playback_position` 은 믹싱 청크 단위 진단값이라 동기화의
증거가 못 된다(명세 8절). 그 둘은 T12·T13 이고 둘 다 not_run 이다.
