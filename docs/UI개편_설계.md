# 하이톤 UI 개편 — 체계와 실행 계획

## 1. 한 문장

화면마다 따로 정하던 크기·색·여백·시간을 **상수 네 뭉치 하나**로 내리고, 그 규칙 위에서 「지금 손이 닿는 것 하나만 밝다」를 열한 화면에 일관되게 세운다.

---

## 2. 디자인 체계

### 2.1 타입 스케일 — 네 단

| 단 | px | 글꼴 | 기본 색 | 쓰는 곳 | 화면당 상한 |
|---|---|---|---|---|---|
| **주연** | 33 | Galmuri11 ×3 | 그 화면의 주인공 색 | 제목 로고 · 런 종료 결과 · 정산 총액 | 1 |
| **머리** | 22 | Galmuri11 ×2 | 이름은 `C_DIM` · 값은 값색 | 화면 이름(x16 · 베이스라인 y34) · 판 안 큰 값 | 이름 1 + 값 1 |
| **본문** | 11 | Galmuri11 | `C_TXT`(주연 줄) / `C_DIM`(나머지) | 물건 이름 · 효과 한 줄 · 목록 행 · 조작 · 상단바 점수 | — |
| **곁말** | 9 | **Galmuri9** | `C_DIM` / `C_OFF` | 레이블 · 조건 · 개수 · 키캡 · 태그 · 목표 | — |

**왜 넷인가, 왜 이 값인가.** `game.gd:23` 주석이 이미 답을 적어 뒀다 — Galmuri11 은 11px 설계라 11·22·33 에서 획이 딱 떨어진다. 지금 실측은 크기가 **열 종**(9×24 · 10×23 · 11×18 · 13×11 · 12×10 · 34×3 · 17×2 · 8×2 · 22 · 18 · 16)이고 이 중 격자에 맞는 것은 11·22 둘뿐이다. 13·17·20 처럼 반 칸 어긋난 크기는 한글에서 곧바로 드러난다 — `ㄹ·ㅃ·ㅌ` 의 획 사이 여백이 1px 이라, 래스터가 반 칸 밀리면 같은 문장 안에서 어떤 세로획은 1px 이고 어떤 획은 2px 로 나온다. 화면이 지저분해 보이는 첫 번째 원인이 이것이고, 다른 무엇을 고치기 전에 이것부터다.

640x360 은 1280x720 으로 정수 2배 확대된다. 11px 은 정확히 22 기기픽셀이 되고, 13px 은 26 이 되는 것이 아니라 **글자마다 다르게** 반올림된다(`canvas_items` 스트레치는 창 해상도로 실제 래스터하므로).

9 가 바닥인 이유: 한글은 자모 셋이 한 칸에 들어가므로 8px 에서 받침이 통째로 사라진다. 9 아래는 없다.

11 과 22 사이가 비는 것은 감수한다. 그 사이를 채우려면 Galmuri14(15px)를 들여야 하고, 파일을 하나 더 들이는 순간 「그 자리에서 새 크기를 만드는」 습관이 되돌아온다. 위계는 크기가 아니라 **색과 여백**이 진다.

`fonts/Galmuri9.ttf` 는 이미 프로젝트에 있는데 한 번도 안 불린다(`FONT_PATH` 하나만 로드). 이번에 `font_sm` 으로 같이 싣는다.

### 2.2 여백 — 4px 격자, 레일 x=16

```
단위      4
덩어리 안  4 또는 8
덩어리 사이 16          (두 배 규칙)
행 높이    11px 글자 → 16 · 9px 글자 → 12
레일       왼쪽 16 · 오른쪽 624 · 위 16 · 아래 344
```

**왜 4인가.** 640x360 ×2 = 1280x720 이므로 4 논리픽셀 = 8 기기픽셀이다. 현대 UI 의 8pt 격자가 배달 해상도에서 그대로 성립한다. 그리고 11px 글자에 16px 행이면 145% — 한글은 라틴보다 획이 많아 130% 아래로 내리면 두 줄이 한 덩어리로 뭉쳐 「읽을 것」이 아니라 「무늬」로 인식된다.

지금 간격은 손으로 섞여 있다: `TIP.pad 7` · `gap 6` · `chip_gap 5` · `tag_lead 2` · `PANEL.pad 6` · `SET.gap 4` · `CARD.gap 14` · `HDR.x 38` · 컬렉션 탭 22 · 격자 19. 세련됨의 절반은 같은 간격이 반복될 때 나온다.

**왜 32 가 아니라 16 인가.** 32 레일은 640 폭에서 좌우 64px(10%)를 먹는다. 컬렉션 격자 한 열이 통째로 사라지는 양이다. 콘솔 타이틀세이프는 TV 오버스캔 전제인데 이 게임은 정수 배율 창이라 근거가 없다. 16 = 4×4 이고, 22px 머리가 x16 에 서면 왼쪽 여백이 글자 높이의 0.7배라 보기에도 맞다.

**예외 하나.** 상시 HUD 는 `x=4` 를 유지한다(`LAY.bank`). 그것은 화면 프레임 크롬이고, `_hud_draw`(4464~4466)가 TITLE·SETTINGS·COLLECT·NEWRUN·RUNINFO·OVER 에서 곧장 반환하므로 **레일 16 을 쓰는 화면과 한 번도 같이 서지 않는다.** 두 정렬 축이 한 화면에 생기는 일이 없다.

### 2.3 색 — 층 여섯, 값 셋, 위험색 없음

```gdscript
const C_BG    := Color("14111f")   # 바닥
const C_PANEL := Color("221d33")   # 판. 유일한 판 색 — lightened/darkened 금지
const C_TXT   := Color("f4efe2")   # 글 1층  판 위 14.2:1
const C_DIM   := Color("9b92b4")   # 글 2층  판 위  5.6:1   (8f86a8 에서 한 단 올림)
const C_OFF   := Color("6b647e")   # 글 3층  판 위  2.9:1   — 꺼진 것 전용
const C_WIRE  := Color("7a7192")   # 선 전용. 글자 금지 (3.6:1)
const C_ACC   := Color("f2b134")   # 초점 — 선택·띠·키캡·조준
const C_GOLD  := Color("f2c94c")   # 돈 — 골드 숫자와 골드 아이콘만
const C_SCORE := Color("8fc9f2")   # 점수  9.1:1
const C_MULT  := Color("e8705c")   # 배수  5.3:1
const C_ODDS  := Color("8fd694")   # 확률  9.5:1
```

**왜 값 셋을 다시 뽑나.** 실측했다. 지금 `C_CHIP #3f8fd8` 과 `C_MULT #e2593f` 의 **상호 대비가 1.07:1** 이다 — 색상만 다르고 명도는 같다. 실눈을 뜨면 같은 회색이고, 12px 안에 든 숫자는 가장자리 몇 픽셀에만 색상 정보가 남으므로 눈은 명도로 먼저 읽는다. 이 게임에서 가장 중요한 두 숫자가 그 단계에서 구별이 안 된다. 새 값은 상호 **1.71:1** 이라 실눈에서 갈린다.

덤으로 `e2593f` 는 판 위 4.44:1 로 팔레트에서 가장 안 읽히는 글자색이었고 `e8705c` 는 5.3:1 이다. `C_DIM 8f86a8`(4.76)도 `9b92b4`(5.55)로 올린다 — 웹의 4.5 기준은 안티에일리어싱된 라틴 본문 전제라, 안티에일리어싱이 없는 1px 획 한글에는 부족하다.

**판 면은 한 색.** 지금 툴팁은 `C_PANEL.lightened(0.06)`, 런 정보는 `C_PANEL.darkened(0.10)` 로 서로 반대 방향이다. 툴팁 판이 밝아서 그 위 배수 붉음이 3.7:1 까지 떨어진다. 판은 `C_PANEL` 하나로 못 박으면 위 대비값이 그대로 전부에 적용된다.

**`.darkened()` / `.lightened()` 를 그리는 자리에서 부르지 않는다.** 지금 25종 넘는 즉석 변형이 있고(`C_TXT.darkened(0.25)` 14회 · `C_DIM.darkened(0.3)` 7회 · `C_DIM.darkened(0.42)` = 2.01:1 을 9px 글자에), 밝기를 호출부가 정하는 한 화면끼리 어긋난다. 색은 위 열한 상수에서만 꺼낸다.

**위험색은 없다.** 붉음은 배수다. 거부는 이미 있는 흔들림(`jx`)이 지고, 못 사는 것은 `C_OFF` 로 꺼지고, 경고는 `C_ACC` + `!` 획 하나가 진다. `_bank_draw` 의 `deny_flash` 가 지금 `C_GOLD → C_MULT` 로 보간하는데 그 하나가 붉음 규약 전체를 무너뜨린다.

**색이 곧 종류다.** 값 셋은 **숫자에만** 붙인다. 레이블·이름·설명·태그 칩에는 절대 안 붙인다. 한 줄에 값색은 하나. `×` 와 `=` 기호는 `C_WIRE` 로 내려 두 색이 안 싸우게 한다.

**재질색**(`C_FELT` · `C_TABLE` · `C_WOOD`)은 **상점·판 선택·보스 제약 세 화면에만**. 재질이 곧 장소다.

### 2.4 선과 면

| 무엇 | 어떻게 | 언제 |
|---|---|---|
| 아무것도 안 그림 | — | 기본값. 여백이 구획한다 |
| 1px 획 | `Color(C_WIRE, 0.24)` | 머리 밑선 y54 x[16,624] · 목록 행 사이 · 정산 합계선 |
| 면 | `C_PANEL` 채움 + 아래 1px `C_BG` | 화면당 떠 있는 면 **하나**. 지금 조작 중인 것 |
| 초점 띠 | 면 윗변 2px `C_ACC` | 면당 하나. 「지금 말 걸고 있는 판」 |
| 사각 테두리 | `draw_rect(..., false, 1.0)` | **금지.** 예외는 판 위 상자 단추 넷 |
| 글자 그림자 | `pos + (0,1)` 에 `C_BG` 로 한 번 더 | 펠트 위 글자만 |
| 둥근 모서리 · 드롭섀도 · 그러데이션 | — | 없음 |

**왜 테두리를 버리나.** `C_PANEL #221d33` 과 `C_BG #14111f` 의 대비는 **1.14:1** 이다. 면만으로는 경계가 거의 안 보이고, 그래서 사면 테두리를 두르게 되고, 두르면 가로 2px + 세로 2px + 안쪽 여백까지 11px 글자 한 줄이 통째로 사라진다. 640x360 에서 2px 테두리는 화면 세로의 0.55% 다. 위 2px + 아래 1px 두 획이 같은 일(「이 면은 앞에 있다」)을 3px 로 한다.

이 어법은 코드 안에 이미 두 군데 있다 — `5116` 행의 런 바 아래 1px 컷, `5219` 행의 자금판 윗변. 새로 발명하는 게 아니라 함수 하나로 뽑아 승격하는 것이다.

```gdscript
func _panel(r: Rect2, focus := false) -> void:
    draw_rect(r, C_PANEL)
    if focus:
        draw_rect(Rect2(r.position, Vector2(r.size.x, 2.0)), C_ACC)
    draw_rect(Rect2(r.position + Vector2(0.0, r.size.y - 1.0),
            Vector2(r.size.x, 1.0)), C_BG)
```

**한글에 외곽선은 안 두른다.** 11px 한글은 획 사이 간격이 1px 이라 외곽선이 그 1px 을 먹어 `ㅁ·ㅇ·ㅂ` 의 속공간이 막힌다. 막힌 속공간은 글자를 무늬로 만든다. 아래로 1칸 내린 단색 그림자는 획을 하나도 안 건드린다.

### 2.5 모션

```gdscript
const MO := {"tap":4, "fast":7, "base":10, "panel":14, "screen":20, "big":28}
func _mo(k: String) -> float: return float(MO[k]) / 60.0
#  67 · 117 · 167 · 233 · 333 · 467 ms

func _e_in(t: float)  -> float: return 1.0 - pow(1.0 - t, 4.0)   # 등장 — 감속
func _e_out(t: float) -> float: return pow(t, 3.0)               # 퇴장 — 가속
func _e_mid(t: float) -> float: return t * t * (3.0 - 2.0 * t)   # 이동 — 대칭
```

- **나감 = 들어옴 × 0.7.** 열림 14f 면 닫힘 10f. 닫기는 이미 마음을 정한 뒤라 같은 시간을 쓰면 붙잡힌다. 지금 `set_t` 하나를 앞뒤로 굴려 대칭이다.
- **스태거 3프레임(50ms), 앞 5개까지, 총 320ms 상한.** 6번째부터는 5번째와 같이 들어온다. 20개를 다 어긋내면 1초가 넘는 로딩으로 보인다. 나갈 때는 어긋나지 않고 한꺼번에.
- **격자 규칙: 이동 거리(px) ≥ 프레임 수.** 10프레임에 6px 을 옮기면 프레임당 0.6px — 서브픽셀이 없으므로 부드러움이 아니라 딱딱거림이다. 못 채우면 **안 옮기고 알파·색으로** 바꾼다. 640x360 의 1px 은 실제로 2x2 덩어리다.
- **상태는 float, 그리기 직전에만 `roundf()`.** 움직임은 부드럽고 찍히는 자리는 격자다. 이것이 `canvas_items` 스트레치의 필수 짝이다 — 엔진은 격자를 지켜 주지 않는다.
- **흔들림은 정보다.** 목표 대비 비율로 3단: 1 / 2 / 3px, `exp(-t*8)` 감쇠, `round()` 필수. 3px 을 넘기면 픽셀 그리드가 깨진 것처럼 보인다. 늘 같은 세기면 세 번째부터 소음이다. 설정에 끄기 한 줄.
- **히트스톱 3~6프레임.** 착탄(`S.FLY→S.RESOLVE`)과 점수 확정. 얼린 동안 소리는 계속 낸다. 3 아래는 안 보이고 6 위는 렉으로 읽힌다.
- **움직이는 것**: 얹힘 띠(행에서 행으로 미끄러짐 `fast`) · 판 밀기(`panel` 열림 / `base` 닫힘) · 숫자 굴림 · 카드 서기 · 상점 물건 낙하 · 탭 표시자.
- **안 움직이는 것**: 목록 행 자체(띠가 움직이고 행은 가만히) · 글자 크기(도트 폰트가 뭉갠다 — 눌림은 1px 내려앉기) · 상시 HUD 등장 · 조준선 · 설정 판 안의 줄 · 재방문하는 화면.
- **되튐은 세 자리만**: 상점 물건 착지(이미 물리) · 희귀 획득 · 보스 제약 확정. 그 밖은 순수 감속.
- **전환 중 입력을 버리지 않는다.** 누르면 도는 것을 그 자리에서 `t=1` 로 밀고 새로 시작한다. `_cup_update` 가 이미 그렇게 한다 — 그 규칙을 판 밀기·탭·숫자 굴림에 복제한다.

## 3. 화면별 실행 계획

한 줄이 한 커밋이다. 위에서부터 손이 적고 효과가 크다. 브랜치 안 딴다.

### 0단계 — 뿌리 (한 곳을 고치면 열한 화면이 따라온다)

---

**C1 · 상수 네 뭉치와 검증기**

- **지금** — 크기 열 종, 색 변형 25종, 시간 상수 화면마다, 여백 8/13/16/19/22/26/28 이 손으로 섞여 있다.
- **바꿀 것** — `game.gd` 상단 `LAY` 위에 `TYPE` · `PAD` · 색 열한 상수 · `MO` · `_e_in/_e_out/_e_mid` · `_panel()` · `_px()/_pr()` 를 세운다. `FONT_PATH` 옆에 `FONT_SMALL := "res://fonts/Galmuri9.ttf"` 와 `font_sm` 을 로드한다. **아직 아무도 안 쓴다.** `scripts/tools/ui_audit.gd` 에 검사 셋을 붙인다 — (1) `draw_string` 크기가 `TYPE` 밖이면 실패 (2) 글자 색 인자에 `.darkened(`/`.lightened(` 가 있으면 실패 (3) 화면 좌표 리터럴이 4의 배수가 아니면 경고.
- **규칙** — 2.1 · 2.3 · 2.5. 이 커밋이 나머지 스물한 개의 채점표다.

---

**C2 · 글자 크기를 넷으로**

- **지금** — `draw_string` 108곳이 9(24) · 10(23) · 11(18) · 13(11) · 12(10) · 34(3) · 17(2) · 8(2) · 22 · 18 · 16 을 쓴다.
- **바꿀 것** — 치환표 하나로 전수 교체. `8·9·10 → 9(font_sm)` · `11·12·13 → 11` · `16·17·18·20·22 → 22` · `34 → 33`. `HDR.sz 20 → 22`, `HDR.sub_sz` 는 안 쓰이므로 유지(뒤에서 지운다). `TIP.title 15 → 16`, `TIP.line 13 → 16`, `TIP.base 10 → 12`.
- **규칙** — 2.1. 9px 이하는 없다. 새 크기를 만들고 싶어지면 색이나 여백으로 푼다.

---

## 4. 안 건드릴 것

이미 옳게 된 것이다. 「거의 갈아엎듯이」는 이것들을 **전 화면 규칙으로 승격하라**는 뜻이지 버리라는 뜻이 아니다.

1. **상점의 펠트 테이블 · 상인 상반신 · 물건이 굴러떨어져 자리를 잡는 물리.** 이 게임의 얼굴이다. 물리 상수(`DROP` 의 `w0 · h0 · vw · om_amp · stag`)는 손대지 않는다. C16 은 가격판의 그리기 순서와 레인 여백만 만진다.

9. **`_cup_update` 의 스프링과 「미끄러지는 도중에 또 누르면 그 자리에서 새로 시작」.** 2.5 의 입력 규칙 원본이다.
10. **설정의 배경 흐림 셰이더와 왼쪽에서 밀려 드는 판.**
11. **`stretch/aspect = "keep"` 전제.** 코드 주석이 근거를 들고 있는 이유가 있다 — 바꾸면 `_tip_pos` 의 clamp 와 상점 계산대 판정이 전부 어긋난다.
12. **판 위는 다트 그대로.** 릴 굴림 · 칩 소리 · 금색 번쩍임은 정산 · 상점 · 골드 같은 판 밖 전용이다. 던지기와 착탄에는 카지노 어휘를 안 올린다.
13. **폰트 import 설정.** `antialiasing=0 · hinting=0 · subpixel_positioning=0` 과 `default_texture_filter=0` 이 이미 맞다. 고칠 것은 요청 크기뿐이다.
14. **`data/` CSV 가 값의 주인.** 밸런스 수치는 여기서 안 만진다.

## 5. 버리는 것

조사에서 나왔지만 이 게임에는 안 쓴다.

| 버리는 것 | 왜 |
|---|---|
| **컬렉션을 딜러 칩 트레이(눕힌 채널)로** | 동전 탭 69개를 옆으로 눕혀 겹치면 개수는 보여도 **무엇이 있나**가 안 보인다. 컬렉션은 훑어 찾는 화면이지 세는 화면이 아니다. 그리고 비용이 「높음」인데 C19 의 세로 레일이 같은 문제(빈 격자 · 진척 표시)를 「보통」에 푼다. |
| **비드 플레이트 스코어보드** | 런 기록을 6×4 색점 격자로. 그 정보를 상단바 `bar_pip` 이 이미 든다. 640x360 에서 같은 것을 두 번 그릴 자리가 없다. |
| **제목 화면을 펠트 테이블로** | 상점이 얼굴이려면 상점만 펠트여야 한다. 제목까지 펠트면 상점에 들어섰을 때 아무 일도 안 일어난다. 재질이 곧 장소라는 규칙(C9)이 이것을 금지한다. |
| **원판·아이콘을 구운 `ImageTexture` 로** | 이 게임은 손그림이다. 이미지 에셋을 하나 들이면 다음부터 「그건 에셋으로」가 기본값이 된다. `draw_circle` 지글거림은 반지름을 정수로 고정하고 중심을 `round()` 하는 것으로 대부분 잡힌다. |
| **`Galmuri14` · `GalmuriMono11` · `Galmuri11-Bold` 추가** | 11·22·33 과 9 로 이미 격자가 선다. 파일 넷을 더 들이면 「그 자리에서 새 크기 만들기」가 되돌아온다. 고정폭 숫자는 폰트가 아니라 `_num()` 의 자리당 고정 advance 7px 로, 손그림으로 푼다. |
| **2×2 체커 디더 타일을 `draw_texture_rect` 로** | 이미지 에셋. 그리고 11px 한글 뒤에 디더가 깔리면 획 사이 1px 여백이 무늬와 섞여 속공간이 죽는다. |
| **CRT 스캔라인 · 강한 비네트** | 9px 한글이 먼저 죽는다. 비네트는 펠트 화면의 네 귀퉁이 `alpha 0.03` ×6겹까지. |
| **32px 세이프 레일** | 640 에서 좌우 64px = 화면의 10%. 오버스캔 근거가 없는 정수 배율 창이다. 16 을 쓴다. |
| **툴팁 안의 태그에 두 번째 툴팁 중첩** | 폭 96px 짜리 둘째 판을 178px 판 옆에 붙일 자리가 없고, 커서가 첫 판 밖으로 나가는 순간 첫 판이 꺼진다. 대신 태그 자체를 짧게 유지한다(C18). |
| **`_goto(s, dir)` 로 화면 전환 전면 통일(밀기/겹침)** | `state = S.X` 가 30곳 넘게 흩어져 있고 판 플레이 중 금지 같은 예외가 많아 한 커밋에 안 들어간다. 그리고 이 게임의 문제는 화면 **사이**가 아니라 화면 **안**이다. 띠·판·탭의 이동만 먼저 세우고, 화면 전환은 다음 회차로. |
| **HUD 를 「하우스는 위 · 내 것은 아래」 축으로 재배치** | 판 플레이는 테이블이 아니다. 그리고 `_panel_rect` 가운데 고정이 상인 실루엣의 전제라 자금판을 앞치마로 내리면 그 전제가 깨진다. |
| **near 레일을 호(arc)로 파기** | `TBL.ny 268` 위에 버튼 줄 · `DROP.w_hi` · 가격판 상한이 전부 직선 전제로 서 있다. 7px 곡선을 얻자고 넷을 다시 유도할 값이 아니다. |
| **카드 숫자를 프레임 밖으로 돌출** | `_row_rect` 가 `gap 14` 로 카드를 안 겹치게 놓는다. 겹침이 없으면 이 기법의 근거(겹침 순서와 무관하게 살아남는다)가 통째로 사라진다. |
| **「점수」·「배수」 글자 라벨 완전 제거** | 발라트로는 라틴 UI 고 색만으로 초회 학습이 된다. 한글 픽셀 UI 에서 첫 등장 레이블 하나는 9px 한 줄로 싸다. 다만 **단위 글자(「점」·「배」·「확률」)는 뺀다** — 색이 이미 그 말을 하고 있고, 툴팁 본문에 해설을 안 쓰는 것과 같은 이유다. |
| **`HDR.sub` 눈썹 두 줄 머리** | 640x360 에서 머리 두 줄은 본문 16px 을 먹는데, 화면 이름이 전부 한 낱말이라 빵부스러기가 할 일이 없다. `sub_dy`/`sub_sz` 는 C2 에서 지운다. |
