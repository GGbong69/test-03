## 2. 결과물 — `outputs/poster/final/`

| 판형 | 캔버스(도련 3mm 포함) | dpi | .psd | .ai | .pdf |
|---|---|---|---|---|---|
| A1 | 4724 × 6669 px | 200 | 101.5MB | 20.1MB | 17.8MB |
| A3 | 3579 × 5031 px | 300 | 64.5MB | 12.9MB | 11.2MB |
| X배너 | 3579 × 10665 px | 150 | 129.1MB | 24.9MB | 24.1MB |

- A1 은 1m 밖에서 보는 크기라 200dpi, A3 는 손에 들고 보니 300dpi, X배너는 실사 출력 관례대로 150dpi.
- A3 는 A1 과 같은 비율(1:√2)이라 **같은 배치를 그대로 줄인다**.
- 색은 RGB. 인쇄소가 CMYK 를 요구하면 포토샵에서 이미지 › 모드 › CMYK 색상.

### 파일마다 하는 일

| 파일 | 쓰임 | 안에 든 것 |
|---|---|---|
| `HIGHTON_*.psd` | 포토샵 편집 | 레이어 묶음 10 — 배경 · 상인 · 진열대 · 소품 · 물건 · 상인 손 · 진열대 앞 · 빛 · 그림자 · 네온 · 제목. 한글 레이어 이름 · dpi · 합친 그림 |
| `HIGHTON_*.ai` | 일러 편집 | 레이어마다 **낱개 이미지 객체 44개**(혼합 · 불투명도 그대로) + 제목은 글꼴 윤곽 **벡터 경로** |
| `HIGHTON_*_ai_kit/` | 일러에서 이름 붙은 레이어로 다시 짓기 | `HIGHTON_*_illustrator.jsx` + `parts/` 낱장 PNG 47장 |
| `HIGHTON_*.pdf` | 인쇄소 | 그림 한 장 + 벡터 제목. 재단 상자 · 도련 상자 |
| `HIGHTON_*_preview.png` | 미리보기 | — |

- 일러는 PDF 의 레이어(OCG)를 무시하고 한 레이어에 다 넣는다. 그래서 `.ai` 를 그냥 열면 이미지 44개가 이름 없이 한 레이어에 든다(하나씩 집어 고칠 수는 있다).
- 레이어 이름까지 원하면 일러에서 **파일 › 스크립트 › 기타 스크립트…** 로 `_ai_kit` 의 `.jsx` 를 고른다. 일러가 직접 `.psd` 와 같은 이름의 레이어 · 하위 레이어를 짓고, 이미지를 심어 넣고(embed), 혼합 · 불투명도 · 숨김을 걸고, 제목을 복합 패스로 그려 `HIGHTON_*_layers.ai` 로 저장한다. `parts/` 폴더는 스크립트 옆에 그대로 둔다.
- 인쇄용 `.pdf` 를 한 장으로 둔 까닭: 인쇄소 장비가 투명 · 혼합을 다르게 풀 일을 없앤다.
- 메타데이터에 포토샵 · 일러가 쓴 척하지 않는다(쓴 프로그램 = 도구 이름). 어도비에서 다시 저장하면 바뀐다.

## 3. 진행

### 3-1. 도구 준비
- **고해상도 렌더** — 게임을 SubViewport 에 달고 논리 640×360 은 그대로, 기기 px 만 키운다(`size_2d_override`). 12배(7680×4320)에서 선 · 숫자 · 글자가 또렷한 것을 확인. 한 변 한계 16384.
- **poster_lib** — 판형 · 도련 · `.psd` 쓰기(RLE · 묶음 · 한글 이름 · dpi) · 벡터 제목 `.pdf`. psd-tools 로 되읽어 합친 그림과 레이어 재합성이 한 점도 다르지 않음을 확인.
- A1 에서만 「BleedBox not in MediaBox」 로 멈추던 것을 고쳤다 — MuPDF 가 페이지 크기를 float32 로 쥐어 0.0001pt 어긋났다.

### 3-2. 세 방향 시안
워크플로우로 세 방향을 실제 크기로 짓고(짓기 → 아트 디렉터 비평 → 고치기), 심사 셋이 견줬다.

| 시안 | 3m 밖 눈길 | 세련됨 | 게임다움 |
|---|---|---|---|
| ① 다트판 정면 — 누아르 벽의 다트판 | 2위 (7) | **1위 (8)** | 3위 (6) |
| ② 상점 테이블 — 상인의 손 · 펠트 · 물건 | 3위 (5) | 3위 (4) | **1위 (8)** |
| ③ 불스아이 순간 — 정상/반전으로 갈린 판 · TV 지지직 띠 | **1위 (8)** | 2위 (6) | 2위 (7) |

**② 상점 테이블**을 골랐다.

### 3-3. 손질
| 차례 | 고친 것 |
|---|---|
| 1차 | main 의 새 팩 겉(포일 봉투) 반영 · 아래 빈 앞판을 높이의 약 10% 로 · 물건을 키워 든 동전 밑을 받치는 호로 · 든 동전은 살짝 들고 그림자는 바로 밑에 · 엄지 · 검지로 테를 집는 손 · 너클 판 누그러뜨림 · 네온을 관처럼(흰 분홍 심 · 좁은 관벽 · 옅은 번짐) · 등급 빛을 매끈하게 · 사진(몬드리안)은 카드로 읽혀 뺌 |
| 2차 | 팔의 원근 휨을 걷어 게임 비율로 · 조끼 · 소매에 테두리 빛 · X배너 물건 간격 조임 |
| 일러 편집 | 「일러에서 개별로 이미지를 넣어줄래? 이러면 내가 편집을 할 수 없는데」 — `.ai` 를 낱개 이미지 객체로, `_ai_kit` 추가 |
| 배치 | 「저울이랑 수금기가 왜 밑에 있어? … 다트판에 왜 넣은거야? 넣지마 그냥」 — **다트판을 뺐다**, 저울 · 등록기는 **게임처럼 진열대 뒤 귀퉁이 · 상인 양옆**(손 · 물건 뒤 층). 빈 자리는 장면을 1.1배 키워 끌어올려 메웠다 |

### 3-4. 지킨 것
- 포스터의 글은 제목뿐. HUD · 단추 · 값 · 안내 글 없음(다트판 숫자도 판을 빼며 함께 빠졌다).
- 상인 얼굴은 안 보인다 — 몸통 윗동은 어둠으로 녹인다. 손은 맨손 + 걷은 소매.
- 도박 그림 없음 — 칩 · 카드 · 룰렛 없음. 둥근 테 동전은 칩으로 읽혀 판 모양 동전으로 갈았다.
- 게임 파일은 안 고쳤다 — HUD 끄기 · 손 자세는 `game.gd` 를 상속한 포스터 전용 스크립트에서만.

## 4. 다시 굽기

```
# 원화(층마다 투명 PNG, 15배) — 창이 있어야 돈다
godot --path . --script scripts/tools/poster/shot_shop.gd

# 판형마다 .psd · .ai · .pdf · _ai_kit · _preview
python scripts/tools/poster/compose_shop.py A1
python scripts/tools/poster/compose_shop.py A3
python scripts/tools/poster/compose_shop.py XB
```

- 원화는 `outputs/poster/shop/raw/`, 결과는 `outputs/poster/shop/` 에 떨어진다(git 제외). 최종본은 `final/` 로 옮기며 이름을 `HIGHTON_*` 으로 바꾼다.
- `--quick` 을 붙이면 합친 미리보기만 빠르게 낸다(배치 잡을 때).
- 배치 값은 `compose_shop.py` 의 `LAYOUT`(판형별 띠 · 제목 · 소품 · 빛) · `GOODS_A` · `GOODS_X`(물건 자리 · 크기 · 돌림).

## 5. 남은 것

- **어도비에서 직접 열어 보지 못했다.** `.psd` · `.ai` · `.pdf` 는 두 가지 파서로 검사했고 `.jsx` 는 문법 검사만 했다. 어도비 PC 에서 처음 열 때 한 번 확인한다.
- 엄지는 가까이서 보면 검지와 나란한 「손가락 둘」로 읽힌다(1m 밖에서는 차이가 거의 안 보인다).
- 손은 게임의 로우폴리, 동전 · 팩은 게임 도트 그림이라 1:1 로 보면 도트가 보인다 — 게임 결 그대로.
